# 渲染站

[English](README.md) | 中文

渲染站让服务器上运行的 agent 把高负载任务交给另一台电脑执行，目前支持 Windows。执行任务的电脑主动通过反向 SSH 隧道连接服务器，因此不需要公网 IP，也不需要开放入站端口。

名字源自它最初的用途：为 qiqi.help 渲染宣传片。

## 术语

| 术语 | 含义 |
|---|---|
| 服务器 | 运行 agent、提交任务的机器，通常是 Linux。 |
| 设备 | 运行渲染站、执行任务的 Windows 电脑。 |
| 渲染站 | 托盘程序 `渲染站.exe` 与后台进程 `station.mjs` 的合称，负责管理任务服务、隧道和设置界面。 |
| 任务服务 | `worker.mjs`，监听设备的 `127.0.0.1:7700`，执行任务。 |
| 工作区 | 设备上登记的一个文件夹。任务只在登记的工作区里运行。 |
| 预设任务 | 工作区文件 `render-station.json` 中定义的任务，服务器可以直接调用，无需逐次审批。 |

## 工作原理

1. 渲染站在设备上启动任务服务，并建立到服务器的反向隧道：`ssh -N -R 77xx:127.0.0.1:7700 -p <端口> <用户名>@<服务器>`。服务器一侧的端口从 7700 开始；端口被失效的旧连接占用时，依次尝试下一个，最大为 7709。
2. 服务器上的命令行工具 `rs`（`cli.mjs`）探测这些端口，找到有响应的任务服务后提交任务。
3. 任务分两类：
   - **预设任务**：调用方按预设的规定带上文件（例如脚本和输入数据），设备在该任务独有的任务目录 `.tools/remote/jobs/<编号>/` 中运行预设的命令，成功后把指定目录中的文件传回服务器。
   - **Shell 任务**：在工作区中执行一条命令，须经设备本地授权（见「Shell 权限」）。
4. 任务产出的文件同时在设备的 `.tools/remote/out/<时间>/` 中保留一份，最多保留最近 30 次任务的结果。

任务服务可以同时执行多个任务：

- 同时运行的任务数由设备的「设置 → 本机 → 同时运行的任务数」决定，默认为 2，范围为 1–16。
- 同一工作区的预设任务默认一次只运行一个，因为它们可能使用相同的文件；工作区文件可以用 `parallel` 放宽。Shell 任务只计入总数。
- 超出上限的任务按提交顺序排队，`rs` 随之等待，并显示前面还有几个任务。排队期间提交方断开连接时，任务取消。排队的任务最多 16 个，超出时新任务被拒绝。

## 环境要求

设备：

- Windows 10 1803 或更高版本，或 Windows 11。使用安装程序时无需另外安装 Node.js 或 Git。
- 能以密钥登录服务器（默认密钥或 ssh-agent 中的密钥）。在终端执行 `ssh -p <端口> <用户名>@<服务器>` 时不提示输入密码，即满足要求。
- WebView2 运行时。缺少时，窗口改用 Edge 的应用窗口打开。
- 预设任务需要的其他软件，由各工作区自行说明。

服务器：Node.js 18 或更高版本，以及本仓库的一份检出。

## 安装

### 设备

1. 下载安装程序：<https://8.137.206.169/assets/render-station/render-station-setup.exe>（约 40 MB，内含 Node.js）。
2. 运行安装程序。安装程序没有代码签名，Windows 可能提示「Windows 已保护你的电脑」，此时单击「更多信息」，再单击「仍要运行」。
3. 单击「安装」。渲染站按当前用户安装到 `%LOCALAPPDATA%\Programs\render-station\`，无需管理员权限；安装完成后自动启动，并在桌面和开始菜单中创建「渲染站」快捷方式。
4. 在窗口的「设置 → 连接」页填写服务器的 SSH 地址和端口，再在「设置 → 工作区」页登记工作区。修改即时保存。

安装程序会先关闭正在运行的渲染站。重新运行新版本的安装程序即可覆盖安装，设置保持不变。卸载时，在 Windows 的「设置 → 应用 → 已安装的应用」中找到「渲染站」，选择「卸载」；卸载时可以选择是否保留设置和任务输出。

也可以直接使用本仓库的检出运行：克隆本仓库，在仓库根目录执行 `npm install`，再双击 `渲染站.exe`。这种方式需要设备已安装 Node.js 和 Git，并通过 Git 更新（见「自动更新」）。`渲染站.exe` 必须与 `station.mjs` 位于同一目录。

### 服务器

克隆本仓库，并在仓库目录中执行 `npm link`，即可安装 `render-station` 和 `rs` 两个命令（见「命令行」）。不执行时，可在仓库目录中改用 `node cli.mjs`。

### 从旧版本迁移

渲染站曾位于 qiqi.help 的 `promo/remote/`。运行安装程序即可完成迁移：安装程序会关闭旧实例，并在新安装的副本没有设置时，复制旧检出中的 `.tools\remote\config.json`，服务器地址、Shell 白名单等设置因此保留。旧版的 `PROMO_*` 设置在把 qiqi.help 的检出登记为工作区时自动导入（见「工作区」）。新实例会重新创建快捷方式和开机自启项，并删除旧的自启项；旧的 `%LOCALAPPDATA%\qiqi-render-station\` 文件夹可以手动删除。

## 配置

配置保存在 `.tools/remote/config.json`，通过窗口的「设置」修改。「设置」分为「连接」「工作区」「权限与审批」「本机」「更新与关于」五页，每项修改即时生效，无需保存。

### 服务器

位于「设置 → 连接」。「SSH 地址」写成 `用户名@服务器`，「端口」为服务器的 SSH 端口，留空时为 22。未填写 SSH 地址时，渲染站不建立隧道。修改后，隧道重新连接。

### 工作区

位于「设置 → 工作区」。每个工作区显示为一栏，列出名称、路径和是否可以使用，单击展开后修改。每个工作区包括：

| 项目 | 说明 |
|---|---|
| 名称 | 服务器调用预设任务时使用的名称。留空时依次取工作区文件中的 `name` 和文件夹名。只能使用字母、数字和「.」「_」「-」，且不能重复。 |
| 路径 | 设备上的文件夹。 |
| 工作区文件声明的设置 | 填写路径后，按工作区文件的 `env` 列出需要填写的项目。必填项缺失时，该工作区的预设任务会被拒绝。 |
| 其他环境变量 | 每行一个，格式为 `名称=值`，同样提供给该工作区的任务。 |

展开工作区后可看到它的预设任务。修改的项目在离开输入框或切换开关时保存。单击「添加工作区」填写名称和路径即可添加；「移除工作区」须确认，不改动文件夹本身。工作区文件修改后，渲染站自动重新读取，无需重启。

添加工作区时（无论在设置页添加还是由服务器添加），如果该文件夹中留有旧版渲染站的 `.tools\remote\config.json`，其中与工作区文件 `env` 对应、且尚未填写的设置会自动导入。

服务器也可以通过 `rs workspace` 添加、修改或移除工作区，是否允许由「设置 → 权限与审批」中的「服务器管理工作区」决定（见「命令行」）。

**登记工作区，即信任它的预设任务。** 预设任务不经审批运行；如果预设允许上传脚本并执行，调用方就可以在设备上以渲染站运行账户的权限运行任意代码。

### 权限与审批

- 「服务器管理工作区」：决定服务器能通过 `rs workspace` 和 `rs ls` 做什么。「关闭」时，服务器既不能变更工作区，也不能查看文件夹；「需要审批」（默认）时，每项变更，以及每次查看已登记工作区以外的文件夹，都须在设备的窗口中批准；「无需审批」时，以上操作都直接执行。
- 「同步剪贴板」：默认关闭，见「剪贴板同步」。
- Shell 任务、YOLO 模式和白名单：见「Shell 权限」。

### 本机

- 「同时运行的任务数」：见「工作原理」。
- 「以管理员身份运行」：位于「总览」页的「本机」中，默认开启。渲染站每次启动时（包括开机自启），Windows 都会通过「用户账户控制」询问是否允许以管理员身份运行；选择「否」时，渲染站以普通权限运行。以管理员身份运行时，预设任务和 Shell 命令也具有管理员权限。以普通权限运行时，可单击「以管理员身份重新启动」再次申请，此时须没有任务运行或排队。关闭此项后，从下次启动起不再询问。

以下开关默认均为开启，关闭即撤销对应的设置：

- 「登录 Windows 后自动启动」：开启后可在任务管理器的「启动应用」中看到。
- 「在桌面和开始菜单中创建快捷方式」。
- 「自动更新」：位于「设置 → 更新与关于」，见「自动更新」。该页还显示当前版本和日志文件的位置，并可打开日志。

## 工作区文件

工作区根目录下的 `render-station.json` 规定该工作区需要的设置和提供的预设任务。没有这个文件的工作区只能运行 Shell 任务。示例：

```json
{
  "name": "video",
  "env": [
    { "key": "FFMPEG", "label": "ffmpeg", "required": true, "placeholder": "C:\\ffmpeg\\bin\\ffmpeg.exe" }
  ],
  "presets": {
    "transcode": {
      "description": "把上传的视频转成 H.264",
      "command": ["node", "{job}/transcode.mjs", "{args}"],
      "upload": ["transcode.mjs", "input/*"],
      "args": ["--crf", "\\d{1,2}"],
      "collect": "{job}/output",
      "timeout": 3600
    }
  }
}
```

qiqi.help 仓库根目录的 `render-station.json` 是一个实际的例子。

顶层的 `parallel`（1–16，默认为 1）规定该工作区的预设任务最多同时运行几个。只有在确认这些任务不会争用同一批文件时，才应调大。

### `env`：需要的设置

| 字段 | 说明 |
|---|---|
| `key` | 环境变量名。 |
| `label` | 设置页显示的名称。 |
| `required` | `true` 表示必填；也可以写平台名（如 `"win32"`），表示仅在该平台上必填。 |
| `placeholder` | 输入框的提示文字。 |
| `hint` | 补充说明。 |
| `type` | `"text"`（默认）或 `"switch"`。开关的值为 `"1"` 或 `"0"`。 |
| `default` | 未填写时使用的值。 |

### `presets`：预设任务

| 字段 | 说明 |
|---|---|
| `command` | 必填。参数列表，第一项是程序；写 `node` 时使用渲染站自己的 Node.js。命令不经过 shell 解释。`"{args}"` 处展开调用方传入的参数，最多出现一次。 |
| `args` | 允许的参数，为正则表达式列表；每个参数必须完整匹配其中一条。省略时不接受参数。 |
| `upload` | 允许调用方带来的文件，为相对路径的 glob（`*` 和 `?` 不跨目录，`**` 跨目录）。服务器按这些 glob 从 `--src` 目录收集文件；设备只接受匹配的文件，并放入任务目录。 |
| `collect` | 命令成功（退出码为 0）后，此目录中的文件传回服务器。 |
| `exclude` | 不传回的文件，为 glob 列表；不含 `/` 的 glob 匹配任意目录下的文件名。 |
| `cwd` | 工作目录，默认为 `{workspace}`。 |
| `env` | 额外的环境变量。 |
| `timeout` | 执行时限，单位为秒，范围 1–86400；省略时不限时。 |
| `description` | 说明，显示在设置页以及 `rs status` 和 `rs presets` 的输出中。 |

`command`、`cwd`、`env` 和 `collect` 中可以使用两个占位符：`{job}` 为任务目录（设备上的 `.tools/remote/jobs/<编号>/`，每个任务独有，任务结束后删除），`{workspace}` 为工作区路径。

## 使用

### 托盘图标

托盘图标的颜色表示当前状态：

| 颜色 | 状态 |
|---|---|
| 绿色 | 空闲，等待任务 |
| 紫色 | 正在执行任务 |
| 黄色 | 正在连接 |
| 红色 | 无法登录服务器，或渲染站无法启动 |
| 灰色 | 已暂停接收任务，或尚未配置服务器 |

单击图标打开窗口。右键菜单包括「打开渲染站」「暂停接收任务」（暂停后为「恢复接收任务」）「重新连接」「在浏览器中打开」「查看日志」和「退出渲染站」。任务完成时，以及服务器的请求等待审批时，系统弹出通知；单击通知即可打开窗口。

### 窗口

窗口由 WebView2 加载 `station.html`，不使用系统标题栏，最小化、最大化和关闭按钮位于页面右上角。拖动页面顶部或左侧导航的空白处可移动窗口，双击可最大化或还原。窗口记住上次的位置、大小和是否最大化。关闭窗口后，页面在后台保留 5 分钟，在此期间再次打开会立即显示。左侧导航包含四项：

- 「总览」：运行状态和进度条、当日统计、最近两分钟的处理器、内存和显卡占用，以及最近的任务及其输出。有多个任务运行或排队时，「运行中」列出各任务及其进度。
- 「输出」：本机保留的任务产出。图片和视频可以直接预览（鼠标悬停时播放视频，单击查看大图，左右方向键切换），其他文件单击后用系统默认程序打开。
- 「动态」：连接过程，以及 ssh 和任务的实时输出。任务的每行输出前标有任务编号。
- 「设置」：分为「连接」「工作区」「权限与审批」「本机」「更新与关于」五页，见「配置」和「Shell 权限」。缺少必填设置时，对应的页名旁显示黄点。

同一页面也可在浏览器中访问：`http://127.0.0.1:7799`。在地址后加 `#gallery`、`#feed`、`#connection`、`#workspaces`、`#access`、`#machine` 或 `#about` 可直接打开对应页面；`#settings` 与 `#connection` 相同。

任务输出中形如 `frame 12/300` 的行会被识别为进度：只有一个任务运行时显示在「总览」的进度条上，多个任务运行时显示在「运行中」列表中。

### 运行状态与日志

设备从睡眠中唤醒、网络中断或任务服务退出后，渲染站会自动重建隧道并重启服务。运行日志位于 `.tools/remote/station.log`，可从托盘菜单的「查看日志」或「设置 → 更新与关于」打开。

隧道建立期间，任何能登录服务器的用户都可以调用设备上的预设任务。不使用时，应在窗口或托盘菜单中选择「暂停接收任务」。暂停后隧道关闭，服务器无法提交任务。

## 命令行

服务器上的 `render-station`（简称 `rs`）用于提交任务和管理设备上的工作区，安装方法见「安装」。完整手册见 [docs/cli.zh-CN.md](docs/cli.zh-CN.md)，其中列出了全部选项、JSON 输出格式和退出码；`rs help <命令>` 显示简要说明。

| 命令 | 用途 |
|---|---|
| `rs status` | 查看设备是否在线、正在运行和排队的任务，以及各工作区。 |
| `rs presets [<工作区>]` | 查看预设任务及其接受的参数。 |
| `rs run <工作区>/<预设任务> [参数…]` | 运行预设任务：从当前目录（`--src`）带上预设所需的文件，并保存任务生成的文件（`--out`）。 |
| `rs shell <命令…>` | 在工作区中执行命令，受 Shell 权限约束。 |
| `rs workspace [list\|add\|set\|remove]` | 列出或变更工作区；`--create` 用于新建不存在的文件夹。 |
| `rs ls [<路径>]` | 列出设备上某个文件夹的内容，或列出设备的磁盘。 |
| `rs clip [ls\|set]` | 读取设备上复制的内容，或写入设备的剪贴板，见「剪贴板同步」。 |

```sh
rs ls F:/
rs ws add video F:/projects/video
rs presets video
rs run video/transcode --crf 23
```

- 所有命令都支持 `--json`，此时只输出一个 JSON 对象。
- 设备上运行的任务数已达上限时，任务排队等待；中断命令即取消任务。
- `rs workspace` 的变更，以及用 `rs ls` 查看已登记工作区以外的文件夹，由设备上的「服务器管理工作区」决定；默认每项请求都须在设备的窗口中批准，最长等待 5 分钟。某个文件夹获准查看后，10 分钟内查看它及其下的文件夹无需再次批准。
- 传给设备的命令和设置值会显示在审批窗口中并写入设备的日志，因此不得在其中包含密钥或密码。

## Shell 权限

渲染站默认不接受 Shell 任务。须在设备的「设置 → 权限与审批」中开启，开启后为 auto 模式。

### auto 模式

- 实际工作目录（解析符号链接后）必须位于所选工作区内。
- 完整命令和工作目录与白名单中的某一条精确匹配时，自动执行。不按解释器或命令前缀放行。
- 未匹配时，请求在渲染站的窗口中等待审批（窗口打开时弹出对话框；托盘图标同时弹出通知，单击即可打开窗口），可选择「拒绝」「仅本次允许」或「允许并加入白名单」。多个请求按提交顺序依次显示。5 分钟内未获批准的任务失败。
- 白名单保存在设备的 `.tools/remote/config.json` 中，可在「设置 → 权限与审批」中删除条目。

### YOLO 模式

- 开启步骤：先让渲染站以管理员身份运行（在 Windows 上，启动时在「用户账户控制」窗口中选择「是」，或在「总览」页单击「以管理员身份重新启动」；其他系统须以 root 运行）；然后在「设置 → 权限与审批」中开启 YOLO 并确认。
- 渲染站检查当前进程是否具有管理员权限，通过后允许任意命令和任意工作目录。没有登记工作区时，工作目录以用户主目录为起点。
- 该模式只保存在内存中。暂停接收任务、重新连接或重启后，恢复为 auto 模式。

### 安全边界

- 任务协议不提供修改白名单或切换 Shell 模式的接口。这些操作只能在设备的设置页完成，服务器无法开启 YOLO 模式。
- 服务器能否登记、修改或移除工作区，为工作区新建文件夹，以及查看工作区以外的文件夹，由设备上的「服务器管理工作区」决定，该设置只能在设备上修改。默认每项请求都须在设备上批准；设为「无需审批」后，能登录服务器的用户即可查看任意文件夹、登记任意文件夹并运行其中的预设任务，效果相当于允许执行任意代码。查看文件夹只能看到名称、大小和修改时间，看不到文件内容。
- 该机制是授权机制，不是操作系统级沙箱。获准的命令可以读写文件，拥有渲染站运行账户的全部权限；目录检查只约束初始工作目录。
- 白名单记录的是命令文本，不固定命令所引用脚本的内容。脚本修改后，同一条命令仍会自动执行。
- 预设任务不经 Shell 白名单审批，信任关系见「工作区」。
- 以管理员身份运行时，渲染站及其运行的一切都具有管理员权限，预设任务或获准的命令可以修改系统设置和任意文件。每次启动都须经 Windows 的「用户账户控制」确认；关闭「以管理员身份运行」即不再询问。
- 拒绝、审批超时或提交方断开连接时，待审批的命令、工作区变更和文件夹查看请求都不会执行。
- 关闭 Shell 权限或暂停接收任务后，后续任务被拒绝，待审批的请求和 YOLO 模式被撤销，排队的任务被取消，已在运行的命令不会被中止。执行超时或提交方断开连接时，渲染站会尝试结束该命令的进程树。
- 模式切换、待审批的请求、人工决定、执行的命令、工作目录、执行结果、工作区变更，以及在工作区以外查看的文件夹，均记录在设备的 `.tools/remote/station.log` 中。

## 剪贴板同步

在「设置 → 权限与审批」中开启「同步剪贴板」后，设备和服务器之间自动同步剪贴板：

- 在设备上复制的文字和图片，约 1 秒内通过 SSH 写入服务器的 `~/.render-station/clipboard/`：最新的一份为 `latest.txt` 或 `latest.png`（图片一律转为 PNG），`history/` 中保留最近 50 份。连续复制时只同步最后一份；隧道未连接时，连接后补发最近的一份。
- 服务器用 `rs clip set` 写入设备的剪贴板，写入的内容不会再同步回服务器。
- 在服务器上，`rs clip` 输出最新的一份（图片则输出其路径），`rs clip ls` 列出历史。这两个命令只读取服务器上的文件，不需要设备在线。
- 密码管理器等程序标记为不记录的内容，以及超过 20 MB 的内容，不会同步。
- 同步时不弹出通知，只在「动态」和日志中记录方向、类型和大小，不记录内容。

```sh
rs clip
git diff | rs clip set
rs clip set --file shot.png
```

## 自动更新

开启后，渲染站在启动 1 分钟后检查一次，此后每 30 分钟检查一次；也可以在「设置 → 更新与关于」中单击「立即检查」。有任务正在运行、排队或等待审批时，等这些全部结束后再更新。更新涉及渲染站自身的文件时，渲染站自动重启；`渲染站.exe` 更新后，托盘程序自动替换为新版本。

**安装程序安装的副本**从更新服务器 `https://8.137.206.169/assets/render-station/` 获取新版本：

- 服务器上的 `latest.json` 列出新版本的每个文件及其 SHA-256，并带有发布密钥的 Ed25519 签名。渲染站只接受签名有效、版本号更高的发布。
- 只下载有变化的文件（`files/<SHA-256>.gz`），逐个校验后再替换；替换失败时全部恢复原状。被替换的文件先改名为 `*.old`，下次启动时删除。
- 安装位置中的 `release.json` 记录当前版本。

**Git 检出**以快进方式合并当前分支的上游分支。通过 `git clone` 得到的检出已设置上游分支。工作树中有未提交的改动或存在未推送的提交时不更新。

## 托盘程序

`渲染站.exe` 的源码为 `exe/station.c`，其行为如下：

- 启动时，先将自身和 `WebView2Loader.dll` 复制到 `%LOCALAPPDATA%\render-station\`，再从该位置运行。因此安装位置（或仓库）中的 exe 不会被占用，更新时可以直接替换。
- 在后台启动 `station.mjs`，进程退出后自动重新启动。优先使用安装位置中的 `node\node.exe`，没有时使用系统安装的 Node.js。
- 将渲染站及其启动的 ssh 和任务进程放入同一个作业对象，退出时一并结束。
- 以普通权限启动时，托盘程序通过「用户账户控制」（`runas`）申请管理员权限，由获准后启动的副本继续运行；存在 `.tools\remote\no-elevate`（即已关闭「以管理员身份运行」）时不申请。选择「否」时以普通权限继续运行。更新后的重启沿用原有权限，不再询问。以管理员身份运行时，仍接受普通权限进程发来的消息：再次启动时打开窗口、安装程序要求退出，以及资源管理器的消息。
- 窗口的位置、大小和是否最大化保存在注册表的 `HKCU\Software\render-station` 中，卸载时删除。
- `渲染站.exe --uninstall` 卸载安装程序安装的副本，Windows 的「已安装的应用」调用的就是它。
- `渲染站.exe --try` 是试运行：在已运行的渲染站旁边打开新编译版本的窗口，连接同一个页面，并带一个单独的托盘图标，用于再次打开窗口或结束试运行。试运行不启动后台进程，不修改开机自启和快捷方式，不申请管理员权限；日志和 WebView2 数据位于 `%LOCALAPPDATA%\render-station\try\`。再次启动试运行时，上一个试运行先退出；窗口关闭 5 分钟后，试运行自动结束。

## 不使用托盘程序运行

先在 `.tools/remote/config.json` 中登记工作区（或用托盘程序登记一次），然后在两个终端中分别运行：

```sh
node worker.mjs
ssh -N -R 7700:127.0.0.1:7700 -p <端口> <用户名>@<服务器>
```

这样运行时没有审批界面，只能执行预设任务，服务器也不能管理工作区或查看文件夹。同时运行的任务数取 `config.json` 中的 `parallel`，默认为 2。

## 已知限制

- 一台服务器只对应一台设备。
- 任务以单个 HTTP 请求的形式同步执行：提交方断开连接（包括隧道中断）时，任务被终止。
- 上传总量不超过 48 MB，传回总量不超过 128 MB。

## 开发

- 测试：`node --test`。
- 编译 `渲染站.exe`：`node exe/build.mjs`。脚本先在 `.tools/exe-build/` 中备齐源码、资源、图标和 WebView2 SDK 的头文件与 `WebView2Loader.dll`（SDK 即 NuGet 包 `Microsoft.Web.WebView2`，解压到 `.tools/webview2/`），再由 `exe/compile.mjs` 编译。编译结果输出到仓库根目录，同时编译安装程序的主体 `.tools/exe-build/setup.exe`。
  - 设备在线且已设置好时，通过预设任务 `render-station/exe` 在设备上编译；否则在本机用 mingw-w64（`x86_64-w64-mingw32-gcc`）交叉编译。加 `--local` 时总在本机编译。
  - 设备上的设置：把渲染站自身的安装文件夹登记为工作区 `render-station`（文件夹中的 `render-station.json` 提供该预设），并把它的 `MINGW` 设为 mingw-w64 的 `bin` 文件夹，例如 [w64devkit](https://github.com/skeeto/w64devkit) 的 `w64devkit\bin`。预设只编译带上的源码，不运行它们。
  - `node exe/build.mjs --try`：在设备上编译后，通过 Shell 任务在设备上以 `--try` 启动新编译的 `渲染站.exe`，须在设备上批准。
- 修改 `exe/` 中的文件后，须重新编译，并将 `渲染站.exe` 与源码一并提交。

### 发布

1. 修改 `package.json` 中的版本号，提交全部改动。
2. `node release/build.mjs`：把已提交的文件、窗口用到的字体和 Windows 版 Node.js（`release/build.mjs` 中的 `NODE`，首次运行时从 nodejs.org 下载并校验）打包，生成签名的 `latest.json`、更新用的 `files/<SHA-256>.gz` 和安装程序，输出到 `.tools/release/out/`。
3. `node release/publish.mjs`：通过 `ssh lu1` 上传到 lu1 的 `/home/user1/apps/render-station/public/`，依次上传文件、安装程序（并把 `render-station-setup.exe` 设为指向它的链接）和 `latest.json`，最后从公网地址读取 `latest.json` 核对。

发布密钥的私钥位于 `.tools/release/key.pem`，不纳入版本控制，公钥写在 `update.mjs` 的 `KEY` 中。私钥须另行备份：丢失后，已安装的副本无法再接受新版本，只能重新安装。

## 文件

| 路径 | 说明 |
|---|---|
| `cli.mjs` | 服务器上的命令行工具，安装后的命令为 `render-station` 和 `rs`。 |
| `docs/` | 命令行手册（`cli.md`、`cli.zh-CN.md`）。 |
| `update.mjs` | 安装副本的更新：校验发布签名，下载、校验并替换文件。 |
| `worker.mjs` | 任务服务：接收任务，排队、执行，并返回结果；转交服务器的工作区变更和文件夹查看请求。 |
| `workspace.mjs` | 工作区文件的读取和校验、glob、预设任务的命令和产出、工作区变更的校验、旧版设置的导入，以及文件夹内容的列出。 |
| `shell.mjs` | Shell 任务的审批、白名单和执行，以及审批队列。 |
| `station.mjs` | 渲染站的后台进程：管理任务服务、隧道和配置，并在 `127.0.0.1:7799` 上提供窗口页面。 |
| `station.html` | 渲染站的窗口页面。 |
| `渲染站.exe` | 托盘程序的编译产物。 |
| `WebView2Loader.dll` | 托盘程序窗口所需的 WebView2 加载器。 |
| `exe/` | 托盘程序的源码（`station.c`、`station.rc`、`station.manifest`）、安装程序的源码（`setup.c`、`setup.rc`）、两者共用的 `common.h`，以及编译脚本：`build.mjs` 备齐文件并选择在哪里编译，`compile.mjs` 调用 mingw-w64 编译。 |
| `render-station.json` | 渲染站自身的工作区文件：安装文件夹登记为工作区后，提供在设备上编译 `渲染站.exe` 的预设任务 `exe`。 |
| `release/` | 发布脚本：`build.mjs` 打包并签名，`publish.mjs` 上传到更新服务器。 |
| `*.test.mjs` | 测试。 |
| `release.json` | 仅存在于安装副本中：当前版本的签名清单。 |
| `.tools/` | 运行时数据（`remote/config.json`、`remote/station.log`、`remote/no-elevate`、`remote/jobs/`、`remote/out/`、`results/`、`update/`）、WebView2 SDK（`webview2/`）和发布用的文件（`release/`），不纳入版本控制。 |
